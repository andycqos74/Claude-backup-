Connecting OneDrive (or OneDrive for Business)

Central Backup stores backups in your own Microsoft account using an OAuth app that you register once. This keeps your data in your tenant and avoids any shared credentials. It works for both personal OneDrive and OneDrive for Business (Microsoft 365).

⚠ Your server needs a DNS hostname, not a bare IP address.

Microsoft rejects redirect URIs that use a raw IP address (e.g. https://87.106.150.130:8443/…) — the authorization fails with invalid_request. The redirect URL must use a hostname such as https://backup.example.com:8443/…. Point a domain (or a free dynamic-DNS name) at your server, set CB_SERVER_NAME to it, restart the server, and open the GUI via that hostname before connecting. The same applies to Google Drive.

1. Register an app in Azure

  1. Go to the Azure app registrations page (search "App registrations" in the Azure / Entra portal) and click New registration.
  2. Name it e.g. Central Backup.
  3. Under Supported account types, choose:
    • OneDrive for Business / M365 only: "Accounts in this organizational directory only".
    • Personal OneDrive (or both): "Accounts in any organizational directory and personal Microsoft accounts".
  4. Under Redirect URI, pick platform Web and paste the redirect URL shown on the Settings page (it looks like https://your-server:8443/api/admin/storage/oauth/callback). It must match exactly.
  5. Click Register.

2. Add API permissions

  1. In the app, open API permissions → Add a permission → Microsoft Graph → Delegated permissions.
  2. Add: Files.ReadWrite, offline_access, and User.Read.
  3. (Business only) If your tenant requires it, click Grant admin consent.

3. Create a client secret

  1. Open Certificates & secrets → New client secret. Give it a description and expiry, then Add.
  2. Copy the secret Value immediately (it is only shown once).
  3. From the app's Overview page, copy the Application (client) ID.

4. Connect in Central Backup

  1. Back on the Settings page, select provider OneDrive.
  2. Paste the Client ID and Client secret, optionally set a destination folder (default central-backup), and click Save app credentials.
  3. Click Connect & authorise, sign in with the Microsoft account that owns the OneDrive, and approve.
  4. You will be returned to Settings showing "connected as <your account>". New backups now go to that OneDrive.

Notes

  • Existing backups are not moved. Snapshots written before the switch stay on the previous backend.
  • Client secrets expire (per the expiry you chose). Before it lapses, create a new secret and re-save + reconnect.
  • Backups are stored as ordinary files under the destination folder; you can see them in OneDrive but should not edit them.
