Connecting Google Drive

Central Backup stores backups in your own Google account using an OAuth app that you register once in Google Cloud. Your data stays in your Drive and no credentials are shared.

⚠ Your server needs a DNS hostname, not a bare IP address.

Google rejects redirect URIs that use a raw IP address — the redirect URL must use a hostname such as https://backup.example.com:8443/…. Point a domain (or a free dynamic-DNS name) at your server, set CB_SERVER_NAME to it, restart the server, and open the GUI via that hostname before connecting.

1. Create a Google Cloud project + OAuth app

  1. Open the Google Cloud Console and create (or select) a project.
  2. Go to APIs & Services → Library, search for Google Drive API, and click Enable.
  3. Go to APIs & Services → OAuth consent screen. Choose External (or Internal if you use Google Workspace), fill in the app name and your email, and save. Add your Google account as a Test user (under Audience) so you can authorise while the app is unverified.

2. Create OAuth credentials

  1. Go to APIs & Services → Credentials → Create credentials → OAuth client ID.
  2. Application type: Web application.
  3. Under Authorized redirect URIs, add the redirect URL shown on the Settings page, exactly: https://your-server:8443/api/admin/storage/oauth/callback.
  4. Click Create and copy the Client ID and Client secret.

3. Connect in Central Backup

  1. On the Settings page, select provider Google Drive.
  2. Paste the Client ID and Client secret, optionally set a destination folder (default central-backup), and click Save app credentials.
  3. Click Connect & authorise, choose your Google account, and approve. If you see an "unverified app" warning, click Advanced → Go to (app) — that is expected for your own app.
  4. You will be returned to Settings showing "connected as <your email>". New backups now go to that Drive.

Notes

  • The app uses the drive.file scope, so Central Backup can only see the files it creates — not the rest of your Drive.
  • Existing backups are not moved. Snapshots written before the switch stay on the previous backend.
  • Backups appear as ordinary files under the destination folder; don't edit them.
